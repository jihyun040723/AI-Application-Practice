# 상식 퀴즈 게임 PRD (Product Requirements Document)

상식 퀴즈 게임의 요구사항을 정리한 문서.

## 1. 프로젝트 개요

- **제품명**: 상식 퀴즈 게임
- **목적**: 여러 분야의 상식을 재미있게 학습하고 테스트할 수 있는 4지선다 퀴즈 게임
- **타겟 사용자**: 중학생 이상, 상식 퀴즈와 학습에 관심 있는 누구나
- **이용 환경**: 데스크톱/모바일 웹 브라우저 (설치·서버 불필요)

## 2. 게임 규칙 (요구사항)

| 항목 | 내용 |
|---|---|
| 문제 유형 | 4지선다 객관식 |
| 카테고리 | 한국사, 세계지리, 과학, 예술과 문화 (4개) |
| 문제 수 | 카테고리별 10문제, 총 40문제 |
| 정답/오답 | 선택 즉시 피드백(정답 표시 + 해설) |
| 최종 결과 | 최종 점수, 정답 개수, 정답률, 카테고리별 결과 |


## 3. 핵심 기능 요구사항

1. **시작 화면**: 제목, 카테고리 안내, [게임 시작] 버튼
2. **문제 화면**: 진행도(N/40), 현재 점수, 진행 막대, 카테고리 표시, 문제와 4개 선택지
3. **피드백**: 정답이면 초록, 오답이면 빨강으로 표시하고 해설 노출. 오답이면 정답도 함께 표시
4. **점수**: 난이도별 점수 — 쉬움 10점, 보통 15점, 어려움 20점 (카테고리당 쉬움 4 / 보통 4 / 어려움 2문제, 만점 560점)
5. **결과 화면**: 최종 점수 / 정답 개수 / 정답률 / 카테고리별 정답 수 / [다시 시작]
6. **키보드 지원**: `1`~`4`로 선택, `Enter`/`Space`로 다음 문제

## 4. 문제 품질 요구사항 (할루시네이션 방지)

- AI가 만든 문제를 그대로 믿지 않고, `CLAUDE.md`의 **교차 검증 가이드라인**으로 검토한다.
- 최상급 표현("가장 큰", "최초의")에는 측정 기준을 명시한다.
- 시점에 따라 변하는 정보는 시점을 명시하거나 출제하지 않는다.
- 논란이 있는 내용은 주류 학설을 기준으로 하거나 출제하지 않는다.

## 5. 3단계 구현 계획

| 단계 | 내용 | 실습 |
|---|---|---|
| 1단계 (MVP) | 핵심 퀴즈 시스템: 프로젝트 구조, 문제 데이터 40개, 게임 진행, 피드백, 결과 | 챕터 07 |
| 2단계 | 점수 시스템(보너스/콤보), 게임 모드(전체/카테고리별/스피드), 힌트 | 챕터 08 |
| 3단계 | 추가 개선(효과음, 오답 노트 등) — 이번 실습 범위 밖 | - |

## 6. 기술 스택

- HTML5, CSS3, Vanilla JavaScript (프레임워크·빌드 도구 없음)
- 파일 구성: `index.html`, `styles.css`, `quiz-data.js`(문제), `quiz-game.js`(게임 로직)

## 7. 성공 기준

- `index.html`을 열면 오류 없이 40문제를 끝까지 진행하고 결과를 볼 수 있다.
- 모든 정답 판정이 데이터의 `answer`와 일치한다.
- 모든 문제가 교차 검증 가이드라인을 통과한다.
